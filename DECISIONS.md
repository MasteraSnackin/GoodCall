# Reusable decisions

The canvas records the decision behind an answer, not just its wording:

- **Maya’s call**: Consider, Skip for now, or Need more context.
- **Who this is for**: the needs and preferences the answer addresses.
- **When to skip it**: reasons to keep an existing product, wait or spend elsewhere.
- **What still needs checking**: limits in the source material and personal context.

New drafts start with conservative suggestions from the linked catalogue and current evidence checks. Maya can edit them with the answer. All fields are part of approval validation; editing any field removes the existing approval. These are local exercise review records, not real creator endorsements.

## Reuse workflow

Approve an answer, then add a new question about the same product and decision topic. The question offers a reviewed starting point. Review it on the canvas and choose **Use as starting point**. This makes a new draft with the new question’s evidence and current product revisions. The original stays unchanged. New context, budget and unsupported-claim checks still apply. Matching suggests a candidate; it does not establish personal suitability.

The Approved advice view is a searchable library of reviewed answers. Publishing creates a follower card containing the answer and all three decision fields. Followers can save the complete snapshot locally and share its encoded link. Later workspace changes cannot update an old link.

## Compatibility and boundaries

Older answers and shared links remain readable without decision fields. No decision guidance is silently added to an existing approved answer. Use **Add decision details** to create suggestions explicitly and return the answer to review.

Source references and reuse metadata remain in the workspace unless explicitly part of the existing public source allowlist. Decision fields are public prose; the editor asks reviewers to keep out personal details and follower handles.

The feature uses local rules, not a connected AI or social inbox. No followers receive messages. Browser automation remains unavailable under the current administrator policy; simulated DOM tests and production compilation do not constitute visual browser acceptance.
